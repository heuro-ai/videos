# Start building a product film

## Use the prepared core

1. Read the private preference/creator/product context when supplied. Use `scripts/studio.py` to prepare a brief, script, storyboard, source assets and provider prompts.
2. Capture one real product interaction and record a founder segment, or obtain an authorized own-avatar segment with a verified voice. Keep original media privately.
3. Read [the acquired-skill guide](research/skill-acquisition.md). Verify local source pins with `python3 scripts/skill_sources.py`; on another environment, `--fetch` retrieves the pinned guidance without executing installers.
4. Use [motion-starter](motion-starter/README.md) for deterministic typography, transitions, spatial panels and supplied founder/product footage. Its package lock makes installation reproducible. Keep demo mode labelled; production mode needs actual footage.
5. Use [the launch-film workflow](workflows/launch-film-production.md), [ten local skills](skills/README.md) and [the launch stack](research/launch-film-stack.md) to choose any additional capture, 3D, map or finishing tool the shot requires.
6. Finish sound, captions and aspect variants, watch the full result and record provenance. Existing `scripts/assemble.py` and `scripts/video.py` provide technical assembly/export utilities.

## Capability boundaries

The motion starter is a reusable technical foundation. It does not automatically capture a signed-in application, create a faithful founder performance, connect a paid model provider, clear footage/music rights or determine whether a film surpasses a creative reference. Those are separate inputs and review steps.

The catalog contains researched alternatives as well as the prepared core. Large checkpoints, GPU services, desktop editors and extra provider accounts are not all installed. Source pins and skill checkouts are not global skill/MCP registration. Use a small stack first, then benchmark a representative sequence before adding heavier tools.
